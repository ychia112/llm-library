# DESIGN.md — Personal LLM Knowledge Base CLI

## Art Direction

- CLI-first, local-first, privacy-first
- Zero cloud dependency. One `.db` file = entire knowledge base.
- Developer audience: Python devs who use ChatGPT/Claude daily

## Problem

LLM chat sessions are siloed. Each session is isolated, unsearchable across platforms,
and wastes tokens by re-asking the same conceptual questions.

## Solution

Ingest → Normalize → Tag → Embed → Query
A CLI tool that turns LLM export files into a personal, queryable knowledge library.

## Data Schema (Normalized Session)

```python
@dataclass
class Session:
    id: str                    # uuid from source platform
    platform: str              # "chatgpt" | "claude" | "gemini"
    title: str
    created_at: datetime
    updated_at: datetime
    messages: list[Message]
    # Auto-generated by tagger:
    topic: str                 # e.g. "Python", "ML", "Web Dev"
    tags: list[str]            # e.g. ["fastapi", "auth", "middleware"]
    question_type: str         # "debug" | "design" | "research" | "howto"
    summary: str               # one-sentence summary
    embedding_id: str          # reference to sqlite-vec row
```

## Platform Export Formats

### ChatGPT (updated Feb 2026)

- Multiple files: conversations-000.json, conversations-001.json (max 100/file)
- Structure: branching tree in `mapping` field (requires tree traversal)
- Key fields: id, title, create_time, update_time, mapping[].message.content.parts

### Claude

- Single conversations.json
- Structure: flat list of chat_messages
- Key fields: uuid, name, created_at, chat_messages[].sender, text

## Tech Stack

| Layer     | Choice                                                          | Reason                                       |
| --------- | --------------------------------------------------------------- | -------------------------------------------- |
| Storage   | sqlite-vec                                                      | Single file, SQL filtering, no server needed |
| Embedding | Gemini API (`gemini-embedding-001`) or `nomic-embed-text` local | Free quota / offline                         |
| Tagger    | Gemini API                                                      | Free 1000 req/day, handles classification    |
| CLI       | Typer                                                           | Simple, typed, auto-generates help           |
| Parser    | Python stdlib                                                   | No extra deps for JSON parsing               |

## Commands (MVP)

```bash
llmlib ingest chatgpt ./conversations-000.json
llmlib ingest claude ./conversations.json
llmlib ask "fastapi middleware auth"
llmlib list --tag python --type debug
llmlib show <session-id>
```

## Vector DB: sqlite-vec

- Single `.db` file at `~/.llmlib/library.db`
- Two tables: `sessions` (metadata) + `session_vectors` (embeddings)
- Query flow: embed query → cosine search → JOIN sessions for metadata filter

## Token Reduction Strategy

Before sending a question to any LLM:

1. Embed the question locally
2. Search `library.db` for cosine similarity > 0.85
3. If hit: return cached answer directly (zero tokens)
4. If partial hit: inject top-3 matching sessions as context (reduced tokens)
5. If miss: proceed to LLM as normal, then ingest the new session
